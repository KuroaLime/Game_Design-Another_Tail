## 1. 목적

기획서 전체가 이 문장 위에 서 있습니다.

> "나의 행동에 대한 피드백을 반영하여 다음 전투가 발생한다면?" — 원본 p.7

원본에는 이 시스템이 **의도로만** 존재했습니다. 무엇을 기록하는지, 몇 번의 표본으로, 무엇을 얼마나 바꾸는지가 없으면 프로그래머는 구현할 수 없고, 심사자는 검증할 수 없습니다. 이 문서가 그 공백을 메웁니다.

### 1.1 이 시스템이 없으면 무너지는 것

| 잃는 것 | 원본 근거 |
|---------|-----------|
| 기획 의도의 유일한 차별점 | p.7 "적들의 AI와 반응은 여전히 일반적 패턴의 반복" 문제 제기가 무효화 |
| 동적 난이도 3축 중 1축 | p.35 "플레이어 행동 기반 패턴 조절" |
| 전투 루프 의사코드 4번 | p.15 "적 객체가 플레이어의 패턴 파악 및 본인 전투 패턴 수정 후 수행" |
| 마케팅 포인트 1번의 설득력 | p.207 "퍼즐형 전략 전투" — 정답 패턴이 고정되면 퍼즐이 아니라 암기 |

### 1.2 설계 원칙

1. **플레이어를 벌하지 않는다.** 잘하면 더 어려워지는 것이 아니라, **다르게** 어려워진다. 총 난이도는 좁은 범위 안에서만 움직인다.
2. **읽을 수 있어야 한다.** 적이 왜 다르게 행동하는지 플레이어가 추론 가능해야 한다. 불투명한 조정은 "게임이 치사하다"는 인상만 남긴다.
3. **입력 난이도는 건드리지 않는다.** 카운터 입력 창(window), 이동 거리, 조작 응답성은 적응 대상이 아니다. 조정 대상은 **적의 선택**뿐이다.
4. **전투 중에는 변하지 않는다.** 적응은 전투와 전투 사이에만 일어난다. 전투 내부에서 규칙이 바뀌면 전술 게임이 성립하지 않는다.
5. **약점은 항상 존재한다.** 속성 내성 상향에 상한을 두어 [속성 시스템](README.md#유지되는-원본-설정)의 핵심 루프(약점→BG→브레이크→연쇄)를 절대 봉쇄하지 않는다.

### 3.2 집계 방식

```
갱신:  전투 종료 시 1회
평활:  EMA(지수이동평균), α = 0.15
       value_new = 0.15 × 이번_전투값 + 0.85 × 기존값
윈도우: 최근 20전투 (n은 20에서 상한)
신뢰도: conf = min(1.0, n / 20)
최소표본: N_min = 8전투. 미만이면 직업 프리셋 프로파일 사용
```

> **α = 0.15 근거** 〔검증필요〕 α가 크면 한두 번의 실험적 플레이가 즉시 반영돼 "적이 눈치가 너무 빠르다"는 인상을 준다. α=0.15는 약 **12~15전투**에 걸쳐 성향 변화가 반영되는 값으로, 플레이어가 빌드를 바꾼 뒤 한 지역을 도는 정도의 시간과 일치한다. 프로토타입 단계에서 0.10 / 0.15 / 0.25 비교 검증.

> **N_min = 8 근거** 튜토리얼(시작의 마을 → 시작의 숲) 구간에서 발생하는 전투 수가 8~12회로 설계되어 있어, 첫 지역을 벗어나는 시점에 프로파일이 활성화된다. 그 이전에는 학습 연출도 노출하지 않는다.

## 5. 규칙

### 5.1 L1 — 개체 행동 선택식

원본 p.75 스킬 테이블에 이미 정의된 `AIWeight`를 기반으로 확장합니다.

```
W_final(skill) = AIWeight_base
               × Π_k ( 1 + Δ_k )
               × S(상황)
               × C(쿨타임·자원 가용)

Δ_k = effect_magnitude_k × conf_k × fire_k

  effect_magnitude_k : 규칙 k의 최대 보정폭 (마스터 데이터, |값| ≤ 0.35)
  conf_k             : 해당 지표의 신뢰도 0.0~1.0
  fire_k             : 트리거 성립 시 1, 아니면 0

S(상황) : 자기 HP 구간, 대상 거리, 아군 수 등 기존 유틸리티 AI 항
C       : 쿨타임 중이거나 MP 부족이면 0 (선택 불가)
```

행동 선택은 `W_final` 기준 **가중 룰렛**으로 뽑습니다. 최댓값 고정 선택(argmax)을 쓰지 않는 이유는 그 자체가 새로운 암기 패턴을 만들기 때문입니다.

### 5.2 대응 규칙 표

12건. `effect_magnitude`는 모두 상한 ±0.35 이내입니다.

| ID | 트리거 (PCP) | 조건 | 대응 | 보정폭 | 설계 의도 |
|----|--------------|------|------|--------|-----------|
| AR-01 | `counter_perfect_rate` | > 0.55 | **다단히트 스킬** 가중치 ↑ | +0.30 | 퍼펙트 카운터는 1회 판정. 다단히트는 판정 횟수가 늘어 완전 무효화가 어려움 |
| AR-02 | `counter_perfect_rate` | > 0.55 | **선딜이 긴 단발 대형기** 가중치 ↓ | −0.25 | 카운터 숙련자에게 헌납하는 행동을 줄임 |
| AR-03 | `counter_try_rate` | < 0.20 | **강타·경직 유발기** 가중치 ↑ | +0.25 | 카운터를 안 쓰는 플레이어에겐 피격 페널티를 체감시킴 |
| AR-04 | `counter_timing_mu` | < −80ms (성급) | **페이크 모션 보유 스킬** ↑ | +0.30 | 빠르게 누르는 습관을 역이용. 입력 창은 건드리지 않음 |
| AR-05 | `engage_range_mu` | > 1200UU (원거리 편중) | **돌진·거리 좁히기** ↑, 원거리 대치 ↓ | +0.30 / −0.20 | 안전 거리 유지 전략에 압박 |
| AR-06 | `engage_range_mu` | < 500UU (근접 편중) | **넉백·이격기, 원거리 배치** ↑ | +0.30 | 붙어서 때리는 전략에 압박 |
| AR-07 | `party_spread_mu` | < 300UU (밀집) | **광역기** 가중치 ↑ | +0.30 | 뭉쳐 다니는 편성을 벌함 |
| AR-08 | `party_spread_mu` | > 900UU (산개) | **단일 집중·고립 대상 처형기** ↑ | +0.25 | 산개 편성의 약점 공략 |
| AR-09 | `elem_dist[X]` | 특정 속성 > 0.45 | 해당 **속성 내성** 부여 | +0.15 (상한 0.40) | §6-3 상한 참조. 봉쇄가 아니라 "덜 잘 통함" |
| AR-10 | `break_per_battle` | > 1.5 | **BG 회복 패턴** 보유 개체 편성 확률 ↑ (L2) | +0.20 | 브레이크 의존 전략에 변수 |
| AR-11 | `mp_starved_ratio` | > 0.40 | **MP 흡수·침묵 유발기** ↑ | +0.25 | 자원 관리 실패를 노림 |
| AR-12 | `heal_hp_threshold` | < 0.30 (늦게 회복) | **연속 타격·도트 부여기** ↑ | +0.25 | 아슬아슬하게 버티는 습관을 노림 |

**규칙 동시 적용 상한** 한 조우에서 발동하는 AR은 **최대 4건**입니다. `priority` 내림차순으로 자르며, 동순위는 `conf` 높은 쪽을 취합니다. 이유는 §6-2.

### 5.3 L2 — 조우 구성

스테이지 진입 시 스폰 테이블의 가중치를 조정합니다. 원본 던전03 배치 설계(p.175)의 "난이도 조절 요소"를 그대로 변수로 씁니다.

| 조정 항목 | 기본 | 적응 범위 | 근거 |
|-----------|------|-----------|------|
| 일반 몬스터 개체 수 | 스폰 테이블 정의값 | ±1마리 | 원본 p.175 "사념의 잔향 배치 밀도 3~5마리" |
| 엘리트 등장 확률 | 스테이지별 정의값 | ×0.8 ~ ×1.25 | — |
| 개체군 구성비 | 스폰 테이블 정의값 | ±20%p | AR-10 등 반영 |
| 조우 간격 | 스테이지별 정의값 | 변경 없음 | 페이싱은 레벨 디자인 영역. 적응 대상 아님 |

**개체 수는 절대 −1 아래로 내려가지 않습니다.** 전투가 너무 쉬워지면 조우 자체가 무의미해집니다. 하향은 밀도가 아니라 DAI(§6-1)로 처리합니다.

### 5.4 L3 — 보스

보스는 조우 시 **1회 확정**되며, 이후 재도전 시에도 값이 유지됩니다(연속 재도전 중 규칙이 바뀌면 학습이 불가능).

| 보스 | 적응 변수 | 조건 | 변화 |
|------|-----------|------|------|
| **심연의 합창단** (던전03) | Phase 2 음정 구체 수 | `chain_rate` > 0.6 | 4개 → **5개**, 구체 회전 주기 −15% |
| | Phase 3 안전 발판 수 | `move_before_act_ratio` > 0.7 | 기본 → **−1개** (이동 의존 성향 압박) |
| | Phase 전환 HP 임계 | `battle_turns_mu` < 8 (속공형) | 70/35% → **75/45%** (페이즈를 건너뛰지 못하게) |
| **타락한 빛: 세레스** (던전02) | 마나 역류 장판 밀도 | `party_spread_mu` < 300 | +1단계 |
| | 보호 필드 재전개 주기 | `break_per_battle` > 1.5 | 2턴 → **3턴** (브레이크 창을 늘려 보상, 대신 필드 내구도 +20%) |
| **리테르나의 정예 기사 아르난** (던전01) | 시간 정지 사용 턴 | `counter_perfect_rate` > 0.55 | 카운터 불가 페이즈 1회 추가 (단, 사전 예고 모션 필수) |
| **최종 보스 (마왕)** | — | — | → 원본 p.20 "성장·선택에 따른 동적 난이도"는 [카르마 문서 §6](02-카르마-명성-시스템.md#6-동적-난이도-연동)에서 별도 정의 |

> **보스 적응이 "보상"으로도 작동해야 하는 이유** 위 표에서 세레스의 보호 필드 항목은 잘하는 플레이어에게 **딜 창을 늘려주는** 방향입니다. 12개 규칙이 전부 압박이면 시스템은 곧 "잘하면 손해"로 읽힙니다. 보스 단위 적응은 압박:보상 = 2:1을 유지합니다.

## 6. 안전장치

이 절이 이 문서에서 가장 중요합니다. 적응형 난이도가 실패하는 방식은 언제나 **폭주**이거나 **불투명**입니다.

### 6-1. DAI 범위 고정

```
DAI = 1.0 + Σ(적용된 AR의 난이도 기여도) + 지역_보정 + 카르마_보정

제약:  0.85 ≤ DAI ≤ 1.20
```

DAI는 적 HP·공격력에 곱해지는 총 배율이 **아니라**, 위 계층들이 만들어낸 결과를 사후 측정한 지표입니다. 계산 결과가 범위를 벗어나면 기여도가 큰 AR부터 순서대로 비활성화합니다.

### 6-2. 동시 적용 4건 상한

12개 규칙이 모두 걸리면 적의 행동이 "플레이어의 모든 습관을 정확히 카운터하는" 상태가 되어 부자연스럽습니다. 4건 상한은 **한 조우에서 플레이어가 인지·대응할 수 있는 변화의 최대치** 〔검증필요〕입니다. 프로토타입에서 3 / 4 / 6 비교.

### 6-3. 속성 내성 상한 40%

AR-09가 반복 발동해도 **단일 속성 내성은 40%를 넘지 않습니다.** 또한:
- 개체가 보유한 **약점 속성은 절대 제거되지 않습니다.**
- 내성이 붙은 속성은 UI에 명시됩니다 → [UI §4.2](03-UI-UX-설계.md#42-인지도-표시)

이 셋이 지켜지지 않으면 속성→BG→브레이크→연쇄 루프 전체가 봉쇄되고, 마케팅 포인트 1번이 사라집니다.

### 6-4. 입력 난이도 불변

**절대 조정 금지 목록**
- 카운터 입력 창(window) 길이
- 퍼펙트 카운터 판정 폭
- 플레이어 이동 거리·속도
- WT 계산식 (원본 p.25)
- 조작 응답 지연

적응은 "적이 무엇을 하는가"만 바꿉니다. "플레이어가 얼마나 정확해야 하는가"는 고정입니다.

### 6-5. 연속 실패 회귀 (Rubber-band down)

```
IF wipe_count(최근 3조우) ≥ 2:
    DAI ← DAI + (1.0 − DAI) × 0.30       # 1.0 방향으로 30% 회귀
    적용된 AR 중 우선도 최하위 2건 비활성화 (다음 5조우간)
    로그: ASSIST_TRIGGERED

IF wipe_count(최근 3조우) ≥ 3:
    DAI ← 1.0 (강제)
    모든 AR 비활성화 (다음 5조우간)
    로그: ASSIST_FULL
```

플레이어에게 이 사실을 알리지 않습니다. 다만 `ASSIST_FULL` 상태에서 클리어하면 도전 과제·랭킹 집계에서 제외 플래그를 붙입니다 〔TBD: 도전과제 시스템 확정 후〕.

### 6-6. 상향 조건

하향은 자동, **상향은 조건부**입니다.

```
IF 최근 3조우 전부 승리 AND party_hp_end_mu > 0.80 AND 사용 아이템 = 0:
    상향 허용 (DAI 상한까지)
ELSE:
    DAI ≤ 1.05 로 제한
```

### 6-7. 챕터 게이팅

| 챕터 | 활성 계층 | 활성 AR |
|------|-----------|---------|
| 1 (튜토리얼 포함) | 없음 | 없음 — 프로파일 수집만 |
| 2 | L1 | AR-01 ~ AR-06 (6건) |
| 3 | L1, L2 | + AR-07 ~ AR-09 (9건) |
| 4 | L1, L2, L3 | 전 12건 |
| 5 | 전 계층 | 전 12건 + 카르마 보정 |

플레이어가 시스템을 배우기 전에 적이 먼저 적응하면 학습 자체가 불가능합니다. 챕터 1은 전면 비활성입니다.

## 7. 플레이어 가시성

원본 p.35의 `[패턴 학습 중…]` 말풍선을 정식 피드백 시스템으로 승격합니다.

### 7.1 인지도(AWR) 등급

개체군별로 플레이어에 대한 "인지도"를 0~3으로 표시합니다. 내부적으로는 해당 개체군에 발동 중인 AR 수입니다.

| AWR | 발동 AR 수 | 표기 | 조우 시 연출 |
|-----|-----------|------|--------------|
| 0 | 0 | — | 없음 |
| 1 | 1 | 「낌새」 | 조우 시 개체가 잠시 플레이어를 응시 (0.4s) |
| 2 | 2–3 | 「경계」 | 조우 시 개체군 전체가 진형을 바꿈 (1.0s) |
| 3 | 4 | 「간파」 | 조우 시 전용 대사 1줄 + 진형 변경 |

### 7.2 도감 표기

몬스터 도감에 **"이 개체가 당신에 대해 아는 것"** 항목을 추가하고, 발동 중인 AR을 자연어로 노출합니다.

```
사념의 잔향  ·  인지도 「경계」

  ▸ 당신이 정면 대치를 선호한다는 것을 알고 있습니다.
  ▸ 당신의 불 속성 공격에 익숙해졌습니다. (내성 15%)

  ※ 인지도는 전투 방식을 바꾸면 낮아집니다.
```

마지막 줄이 중요합니다. **플레이어에게 대응 수단이 있다는 것**을 명시해야 시스템이 압박이 아니라 게임플레이가 됩니다.

### 7.3 인지도 낮추기

| 방법 | 효과 |
|------|------|
| 해당 지표를 반대 방향으로 이동 | 자연 감소 (EMA에 따라 12~15전투) |
| 다른 지역으로 이동 | 개체군이 다르면 AWR 0부터 시작 |
| 「망각의 향」 소비 아이템 | 해당 개체군 AWR 즉시 −1 (24 게임시간 유지) → [아이템 특수 계열](README.md#유지되는-원본-설정) 에 추가 |

## 9. 구현 부하 추정

원본 팀 구성(p.211)의 **AI·전투 프로그래머 3명 × 30개월** 배정이 이 시스템의 근거가 됩니다.

| 작업 | 인월 | 담당 |
|------|------|------|
| PCP 수집·집계 파이프라인 | 3 | AI·전투 |
| AR 평가 엔진 + 마스터 데이터 툴 | 5 | AI·전투 + 툴 |
| L1 행동 선택식 통합 (기존 유틸리티 AI 확장) | 6 | AI·전투 |
| L2 스폰 테이블 연동 | 2 | 게임플레이 |
| L3 보스별 개별 구현 (3보스 + 최종) | 8 | AI·전투 |
| 안전장치 + 텔레메트리 | 4 | AI·전투 + 백엔드 |
| 도감·인지도 UI | 3 | UI·시스템 |
| 밸런싱 이터레이션 | 12 | 시스템 디자이너 |
| **합계** | **43 인월** | |

3명 × 30개월 = 90 인월 중 43 인월(48%)이 적응형 AI에 투입됩니다. 나머지는 일반 몬스터 AI, 파티원 AI, 패스파인딩입니다. **배정은 타당하나 여유가 크지 않습니다.**
