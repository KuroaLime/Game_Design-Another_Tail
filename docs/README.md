## 작성 규약

실무 기획서로 제출하기 위해 아래 규약을 지킵니다. 원본 덱이 지적받을 수 있었던 지점들을 규약으로 고정한 것입니다.

### 1. 모든 수치에는 근거가 붙는다
```
❌  화상 확률 15%
✅  화상 확률 15% — 불은 기본 딜 보정 +10%로 상위권이므로 상태이상 확률은 평균값.
    상태이상은 전투 체감이 커 30% 이상은 과도, 10~20%를 기준선으로 둔다. (원본 p.50 기준 유지)
```

### 2. 미확정 값은 숨기지 않고 표시한다
- `〔TBD〕` — 아직 정하지 않음. 반드시 담당·기한과 함께.
- `〔가정〕` — 검증 없이 세운 값. 검증 방법을 함께 적는다.
- `〔검증필요〕` — 플레이 테스트로 확인해야 하는 값.

### 3. 시스템 문서는 아래 8개 절을 갖춘다
1. 목적 — 이 시스템이 없으면 무엇이 무너지는가
2. 용어 정의
3. 데이터 — 무엇을 저장하는가 (스키마)
4. 규칙 — 계산식, 상태 전이
5. 파라미터 표 — 조정 가능한 값과 기본값
6. 안전장치 — 고장 났을 때 어떻게 막는가
7. 검증 — 어떻게 "제대로 동작한다"고 판정하는가
8. 미해결 이슈

### 4. 다른 문서를 참조할 때는 위치까지 적는다
`→ [적응형 AI §5.2](01-적응형-전투-AI.md#52-대응-규칙-표)` 형태.
원본 덱을 참조할 때는 `원본 p.49` 형태로 물리 페이지를 적는다.

### 5. 템플릿 복사 금지
새 스테이지·몬스터를 추가할 때 기존 항목을 복사한 뒤 일부만 고치는 방식은 금지합니다.
원본 덱에서 발생한 오류 25건 중 7건이 이 방식 하나에서 나왔습니다. → [정오표](00-정오표.md)
