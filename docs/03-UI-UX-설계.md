# 03. UI / UX 설계

> **문서 상태** 1차 확정 · UI 아티스트 착수 가능
> **원본 근거** p.21 (키맵), p.25 (WT 턴 순서), p.27–29 (행동 트리·카운터), p.46–48 (연쇄·브레이크), p.203–205 (커맨드 UI 레퍼런스, 메뉴 8종)
> **연관 문서** [01 적응형 AI §7](01-적응형-전투-AI.md#7-플레이어-가시성) · [02 카르마 §9](02-카르마-명성-시스템.md#9-ui-요구사항)
> **기준 해상도** 1920×1080 (16:9). 이하 좌표는 이 기준. UI 스케일 80~130% 지원.

## 1. 목적

원본의 UI 챕터는 3페이지였고, 그중 실질 내용은 레퍼런스 이미지 1장과 메뉴 목록 1개였습니다(p.203–205). 반면 이 게임이 한 화면에서 동시에 보여줘야 하는 정보는 다음과 같습니다.

- WT 기반 턴 순서 (가변 길이)
- 적 HP **와 별도의** 브레이크 게이지 (원본 p.47)
- 속성 연쇄 진행 상태 (1차 속성이 걸린 대상과 유효 시간, 원본 p.46)
- 상태이상 16종 (원본 p.45)
- 격자 이동 가능 범위 (원본 p.28)
- 카운터 입력 창 (원본 p.29 — 실시간 입력)
- 파티 4인의 HP / MP / WT
- 적응형 AI 인지도 ([01 §7](01-적응형-전투-AI.md#7-플레이어-가시성))

**이 정보량이 곧 이 게임의 UI 난이도입니다.** 정보 표시 설계 없이는 시스템의 깊이가 그대로 조작 스트레스로 바뀝니다.

### 1.1 설계 원칙

1. **한 번에 하나의 결정.** 행동 선택 → 대상 선택 → 확인. 각 단계에서 필요한 정보만 강조하고 나머지는 감광(dim)한다.
2. **BG는 HP와 같은 급의 정보다.** 브레이크가 전투의 핵심 루프이므로 게이지를 부속물로 그리지 않는다.
3. **카운터는 절대 가리지 않는다.** 실시간 입력이 요구되는 유일한 요소이므로 화면 하단 중앙 고정, 어떤 팝업도 그 위에 오지 않는다.
4. **약점은 알아낸 것만 보여준다.** 전부 노출하면 탐색의 재미가, 전부 감추면 전략이 사라진다. → §3.4
5. **텍스트 없이도 읽힌다.** 색만으로 정보를 전달하지 않고 형태·아이콘을 병행한다(§8).

## 2. 정보 계층

모든 UI 요소를 3단으로 분류합니다. 이 분류가 화면 배치의 근거입니다.

| 단계 | 정의 | 표시 | 예 |
|------|------|------|-----|
| **L0 상시** | 없으면 판단 불가 | 항상 표시 | 턴 순서, 파티 HP/MP, 대상 HP/BG, 카운터 프롬프트 |
| **L1 조건부** | 특정 상태에서만 유효 | 조건 성립 시 자동 | 연쇄 각인, 상태이상 아이콘, 이동 범위, 인지도 뱃지 |
| **L2 요청** | 깊은 정보 | 키 입력 시 | 상세 스탯, 스킬 툴팁, 적 도감, 데미지 계산 내역 |

### 3.2 ① 턴 순서 타임라인 — WT 시각화

원본 p.25의 WT 계산식(민첩 + 특성 + 클래스 가중치 + 장비 무게 + 상황 가산)은 **플레이어가 결과만 보고 원리를 추론할 수 있어야** 전술이 성립합니다.

```
좌표      x: 40 ~ 900,  y: 24 ~ 72
표시 수   현재 턴 포함 8개체
정렬      WT 내림차순 (원본 p.25 규칙)

▸ [현재] [+1] [+2] [+3] [+4] [+5] [+6] [+7]
   96×48  72×40 (이후 동일)

각 칸 구성
  ├ 초상 (아군=청색 테두리 2px / 적=적색 테두리 2px)
  ├ 하단 WT 수치 (tabular, 10px)
  └ 상태 아이콘 최대 2개 (초과 시 "+N")
```

**필수 인터랙션**
| 상황 | 표시 |
|------|------|
| 합동 공격(원본 p.27) 대상 지정 | 해당 아군 칸에 사슬 아이콘. **WT가 소모되어 뒤로 밀리는 위치를 미리보기로 표시** |
| 아이템·기술로 WT 변동 예상 | 이동할 위치에 반투명 고스트 칸 |
| 퍼펙트 카운터로 WT 회수(원본 p.29) | 칸이 앞으로 이동하는 0.3s 애니메이션 + 청색 플래시 |
| 브레이크로 인한 턴 지연(원본 p.47) | 해당 적 칸이 뒤로 밀리며 적색 균열 이펙트 |

> **미리보기가 없으면 합동 공격은 사용되지 않습니다.** 원본 p.27은 "같이 행동하는 객체의 WT도 소모된다"고만 정의했는데, 얼마나 손해인지 보이지 않으면 플레이어는 안전한 단독 행동만 반복합니다.

### 3.3 ② 대상 정보 패널 — HP와 BG

```
좌표      화면 중앙 상단, x: 660~1260, y: 120~280
표시 조건 L0 (대상 조준 중) / 비조준 시에는 적 머리 위 축약형 바만
```

| 게이지 | 색 | 형태 | 근거 |
|--------|-----|------|------|
| HP | 적색 계열 `#C0392B` | 실선 채움, 높이 14px | 관습 |
| **BG** | 청록 `#16A085` | **빗금 채움(▓), 높이 10px** | 색맹 대응 + HP와 형태로 구분. §8 |

**BG 표시 규칙**
- 수치 병기 필수 (`62/160`). 원본 p.51의 BG 감소 보정이 속성별로 다르므로(0~30%) 플레이어가 "이 스킬로 몇 대면 깨지는지" 계산할 수 있어야 함.
- 브레이크 임박(BG ≤ 20%) 시 게이지 테두리 점멸 0.8s 주기.
- 브레이크 진입 시 **0.6s 전용 연출** — 게이지가 유리처럼 깨지고 대상에 균열 데칼. 이후 잔여 턴 수를 게이지 자리에 표시(`BREAK 2턴`).

**약점 표시 (§1.1-4 규칙)**
```
약점 ?  ?  ⚡
```
- 미판명 속성은 `?`. 한 번이라도 해당 속성으로 유효타를 넣으면 아이콘으로 확정 표시.
- 판명 정보는 **개체군 단위로 세이브에 영구 저장** — 같은 종을 다시 만나면 이미 알고 있음(도감 연동).
- [적응형 AI AR-09](01-적응형-전투-AI.md#52-대응-규칙-표)로 내성이 붙은 속성은 아이콘 위에 방패 오버레이 + 수치(`🔥🛡15%`). **감추지 않습니다.**

### 3.4 ③ 속성 연쇄 각인

원본 p.46의 연쇄는 "A 속성 적중 후 B 속성 적중"이 조건입니다. **1차 속성이 걸려 있다는 사실과 남은 시간이 보이지 않으면 연쇄는 우연으로만 발생합니다.**

```
각인 🔥 (2턴)
```

| 규칙 | 값 |
|------|-----|
| 각인 유효 턴 | 2턴 〔검증필요〕 |
| 표시 위치 | 대상 정보 패널 + 필드 상 대상 머리 위 (L1) |
| 연쇄 가능 알림 | 커맨드 링에서 **연쇄를 성립시키는 스킬에 링 테두리 발광** |
| 연쇄 성립 시 | 0.5s 카메라 줌 + 조합명 텍스트(`불 + 바람 — 연소 확산`) + 추가 효과 로그 |

원본 p.52의 4조합(불+바람, 물+번개, 물+얼음, 독+불)은 **스킬 툴팁에도 표기**합니다: `이 스킬은 🔥 각인 대상에게 연쇄를 일으킵니다`.

### 3.5 ④ 격자 및 이동 범위

원본 p.28 — A×A칸 이동, 턴 내 1회, 이동 후 행동 가능.

```
이동 가능      청색 반투명 타일 (알파 0.25) + 경계선
이동 후 공격권  주황 외곽선 (이동 지점 기준 사거리 미리보기)
적 위협 범위    적 조준 시 적색 사선 패턴 (토글: T키)
차폐물          원본 p.34의 환경 오브젝트(바위·통나무·덤불)에 아이콘 뱃지
```

**환경 오브젝트 상호작용 표시** — 원본 p.34가 약속한 "환경을 활용한 연쇄 반응, 환경 파괴 및 조작"은 오브젝트에 **가능한 상호작용을 아이콘으로 명시**해야 발견됩니다.
| 아이콘 | 의미 |
|--------|------|
| 🔥 | 화염 속성으로 점화 가능 (연소 확산) |
| ⚡ | 전도체 — 번개 속성 광역화 |
| ↘ | 파괴 시 낙하 데미지 |
| 🛡 | 엄폐 가능 |

### 3.6 ⑥ 카운터 프롬프트

원본 p.29 — 카운터는 이 게임에서 **유일한 실시간 입력**입니다. 최우선 순위 UI.

```
좌표      x: 760~1160, y: 880~940  (화면 하단 중앙 고정)
레이어    최상위. 어떤 팝업·로그·컷인도 이 영역을 덮지 않는다
표시      적 공격 모션의 지정 프레임에서 시작

┌────────────────────────┐
│   ◀━━━━━█━━━━▶   [F]   │
└────────────────────────┘
      ↑     ↑
   입력창  퍼펙트 구간
```

| 요소 | 스펙 |
|------|------|
| 전체 입력 창 | 400ms 〔검증필요〕 |
| 퍼펙트 구간 | 중앙 120ms |
| 시각 신호 | 커서가 좌→우로 이동. 퍼펙트 구간은 금색 |
| 청각 신호 | 창 시작 시 단발음. 퍼펙트 구간 진입 시 반음 상승 (시각 장애 대응) |
| 성공 | 퍼펙트=금색 폭발 + `PERFECT` + WT 회수량 표기 / 일반=은색 + `COUNTER` |
| 실패 | 표시 없음 (실패를 강조해 스트레스를 주지 않음) |
| 방어 기술 사용 시 | 프롬프트 대신 방패 아이콘 + 방어 수치 vs 공격력 비교 표시 (원본 p.29 판정) |

> **적응형 AI와의 계약** [01 §6-4](01-적응형-전투-AI.md#6-4-입력-난이도-불변)에 따라 **입력 창 400ms와 퍼펙트 120ms는 어떤 경우에도 변하지 않습니다.** AR-04(페이크 모션)는 모션을 바꿀 뿐 창을 줄이지 않습니다. UI는 이 계약을 시각적으로도 보장해야 하므로 프롬프트 바의 길이는 항상 동일합니다.

### 3.7 ⑤ 파티 상태

```
좌표   x: 40~560, y: 940~1050
구성   4열. 미영입 슬롯은 비활성 표시

각 칸
  ├ 이름 (12px)
  ├ HP 바 + 수치        높이 10px
  ├ MP 바 + 수치        높이 8px
  ├ WT 잔량 (●●●○)      4단계 도트
  ├ 상태이상 아이콘 최대 3 (+N)
  └ 관계도 링 (초상 테두리) — Bond 단계별 색  → [02 §4.1](02-카르마-명성-시스템.md#41-정의와-효과)
```

**합동 공격 가능 표시** — 두 아군이 합동 조건을 만족하면 두 칸 사이에 사슬 아이콘이 연결됩니다. 관계도가 높을수록 링이 밝아져 **[02 문서의 연계 보정(최대 +35%)이 화면에서 읽히게** 합니다.

### 3.8 ⑦ 커맨드 링

원본 p.204의 방사형 레퍼런스를 계승하되, 원본 예시의 `GUN`/`STACK`은 이 게임에 없는 개념이므로 교체합니다.

```
6방향 링 (원본 행동 트리 p.27 기준)

        SKILL
   ATTACK    ITEM
        ●
   MOVE      TACTIC
        GUARD

ATTACK  무기 일반 공격
SKILL   직업 스킬 / 합동 공격 / 공통 기술  → 서브 링
ITEM    전투 아이템 / 회복 아이템
GUARD   방어 기술 (공통 기술, AP+WT 소모)
MOVE    이동 (턴 내 1회)
TACTIC  작전 지시 (원본 p.31: 지형 전술 / 행동 전술)
```

| 스펙 | 값 |
|------|-----|
| 반경 | 120px |
| 입력 | 마우스 방향 + 좌클릭 / 키보드 방향키 + Space / 게임패드 스틱 |
| 열기 | 자기 턴 시작 시 자동 (fade-in 0.15s) |
| 서브 링 | 상위 항목 선택 시 링이 확장(반경 180px). 뒤로가기 = 우클릭 / ESC |
| 비활성 | 자원 부족·쿨타임 항목은 감광 + 사유 툴팁 |
| **연쇄 발광** | 현재 각인 상태에서 연쇄를 성립시키는 항목은 테두리 발광 (§3.4) |
| 도망치기 | 링에 두지 않음. `Q` 홀드 1.2s (오조작 방지) |

`MOVE`를 링에 넣은 이유 — 원본 p.28은 이동을 행동과 분리된 단계로 정의했지만, 링에 없으면 "이동 후 행동" 순서가 강제로 느껴집니다. 링에 두면 이동을 건너뛰고 바로 행동하는 선택이 동등하게 보입니다.

## 4. 적응형 AI 피드백

→ 시스템 정의는 [01 §7](01-적응형-전투-AI.md#7-플레이어-가시성)

### 4.1 조우 시 연출

| AWR | 연출 | 지속 |
|-----|------|------|
| 0 | 없음 | — |
| 1 「낌새」 | 개체가 플레이어를 응시. HUD 우상단에 뱃지 fade-in | 0.4s |
| 2 「경계」 | 개체군 전체 진형 변경 애니메이션 + 뱃지 | 1.0s |
| 3 「간파」 | 전용 대사 1줄(자막) + 진형 변경 + 뱃지 점멸 1회 | 1.6s |

**연출은 전투 시작 전에 끝납니다.** 전투 중 인터럽트는 금지 (§1.1-3의 카운터 우선 원칙과 충돌).

### 4.2 인지도 표시

```
HUD 우상단   x: 1560~1880, y: 24~72

┌──────────────────┐
│ 👁 「경계」  AWR 2 │   ← 클릭 시 도감 해당 항목으로 이동
```

```
│                                                          │
```

## 8. 접근성 및 가독성

턴제 전술 게임에서 접근성은 선택이 아니라 **상태이상 16종과 속성 13종을 구분해야 하는 구조적 요구**입니다.

| 항목 | 기준 |
|------|------|
| 색 단독 의존 금지 | 모든 속성·상태이상은 색 + **고유 실루엣 아이콘** 병행. 흑백 출력 시에도 구분 가능해야 함 |
| 대비 | 텍스트 대비 4.5:1 이상 (WCAG AA). 게이지 대비 3:1 이상 |
| 최소 폰트 | 본문 14px, 수치 12px @1080p. UI 스케일 80~130% |
| 카운터 청각 신호 | §3.6 — 시각 신호와 1:1 대응하는 음 신호 필수 |
| 색맹 모드 | 3종(적록·청황·전색). 속성 팔레트와 HP/BG 팔레트를 각각 재매핑 |
| 카운터 보조 모드 | 입력 창 ×1.5 옵션 (도전과제 제외 플래그 없음 — 접근성 옵션은 벌하지 않음) |
| 자동 전투 | 반복 전투 대상. 보스전 비활성 |
| 텍스트 속도 · 자동 진행 | 대사 창 필수 옵션 |
| 진동 | 카운터 창 시작 시 짧은 진동 (게임패드) |
| 모션 감소 | 화면 흔들림·연쇄 줌 연출 축소 옵션 |

> **카운터 보조 모드에 페널티를 두지 않는 이유** [01 §6-4](01-적응형-전투-AI.md#6-4-입력-난이도-불변)는 적응형 AI가 입력 난이도를 건드리지 못하게 막습니다. 같은 논리로 접근성 옵션도 보상을 깎지 않습니다. 입력 정확도는 이 게임이 평가하려는 능력이 아닙니다 — 평가 대상은 **속성·빌드·배치의 판단**입니다.
